# Python HSE Hub

Закрытый сайт курса по Python: занятия, задачи с семинаров, решения студентов и доклады по
библиотекам — в одной базе знаний с поиском и фильтрами. Студенты читают и предлагают свои
решения и доклады, преподаватель ведёт курс и модерирует заявки.

## Возможности

- **База знаний** — общая лента задач и докладов: фильтры по типу, группе, студенту, тегу,
  полнотекстовый поиск по-русски; фильтры живут в ссылке.
- **Занятия и задачи** — условие с формулами и подсветкой кода, кто решал у доски, вердикт,
  время и память, опубликованные решения («разобрано у доски» — первым).
- **Python в браузере** — редактор, `input()`, автотесты задачи; Pyodide в Web Worker с таймаутом
  и отключённой сетью.
- **Заявки** — студент выбирает себя по PIN и предлагает решение или доклад (Markdown, картинки,
  соавторы); статусы и комментарии преподавателя в «Моих заявках».
- **Админка** — занятия, задачи, решения, доклады, группы и студенты (импорт списком, сброс PIN,
  запрет заявок), обзор группы «студент × задачи», очередь модерации, настройки.
- **Антифрод** — лимиты на вход и PIN, очередь ≤ 3 заявок, 60 с между отправками, суточные лимиты,
  дубликаты по хэшу, honeypot, журнал действий.
- **Автоэкспорт в GitHub** — после каждой публикации репозиторий курса пересобирается по датам.

## Стек

Next.js 15 (App Router, Server Actions) · React 19 · TypeScript · Tailwind 3 · Supabase (Postgres +
Storage, доступ только с сервера) · zod · jose · bcryptjs · unified/remark/rehype + KaTeX · Shiki ·
Pyodide · Vitest · Playwright.

## Запуск локально

```bash
npm install
cp .env.example .env.local   # заполнить значения, см. комментарии в файле
npm run dev                  # http://localhost:3000
```

База: миграции в `supabase/migrations/` (применяются по порядку), тестовые данные для dev —
`supabase/seed.sql` (пароль курса `python-dev`). **Seed не запускать на проде.**

| Команда                                                              | Что делает                                                                   |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `npm run dev`                                                        | dev-сервер                                                                   |
| `npm run typecheck` · `npm run lint`                                 | проверки                                                                     |
| `npm test`                                                           | юнит-тесты (Vitest)                                                          |

## Деплой (Vercel + Supabase)

1. Создать Supabase-проект для прода и применить все файлы из `supabase/migrations/` по порядку.
2. Выставить `.env.local` на прод-проект и выполнить `npx tsx scripts/init-settings.ts '<пароль курса>'`.
3. В Vercel импортировать репозиторий и задать переменные окружения: `SUPABASE_URL`,
   `SUPABASE_SERVICE_ROLE_KEY`, `SESSION_SECRET`, `TEACHER_PASSWORD_HASH` (сырой хэш, без `\$`),
   при необходимости `GITHUB_EXPORT_TOKEN`, `GITHUB_EXPORT_REPO`, `GITHUB_EXPORT_BRANCH`.
4. `main` → прод, пулреквесты → превью.

## Безопасность

- Ключ service role живёт только на сервере; RLS включён на всех таблицах без политик, у ролей
  `anon`/`authenticated` нет прав — публичный ключ не читает ничего.
- Каждая мутация — Server Action с проверкой роли, zod-валидацией и записью в `audit_log`.
- Markdown рендерится без сырого HTML, ссылки и картинки проходят через белый список.
- Заголовки: `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, HSTS.
